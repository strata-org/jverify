# Bytecode-frontend xfail manifest.
#
# The verification corpus is owned by StrataJavaFrontEnd (JFE) and shared
# verbatim; its @JVerifyTest annotations encode the SOURCE frontend's
# expectations. This manifest overrides the xfail decision for the BYTECODE
# frontend per test class, so the shared corpus stays a single source of
# truth and the bytecode frontend never edits JFE's fixtures.
#
# Format (whitespace-separated), one entry per line:
#   XFAIL  <fully.qualified.ClassName>  <BLOCKER>  <reason...>
#     Treat as an expected failure on the bytecode frontend even though the
#     shared annotation does not mark it expectedToFail. The engine runs it
#     and inverts the outcome (failure -> skip; unexpected pass -> XPASS).
#   RUN    <fully.qualified.ClassName>  <reason...>
#     Run normally on the bytecode frontend even though the shared annotation
#     marks it expectedToFail (the source-frontend gap does not apply here).
#
# Blank lines and lines beginning with '#' are ignored. BLOCKER values are
# names of org.strata.jverify.testengine.Blocker.

# ============================================================================
# Diverging refusals: JFE refuses the construct with a reason bf does not
# reproduce, because bf translates the form javac leaves behind.
# ============================================================================
XFAIL  org.strata.jverify.verifier.tests.javasupport.lambdas.PolymorphicLambdas                   FRONTEND_DISPATCH  type-variable method refusal diagnostic not reproduced
SKIP   org.strata.jverify.verifier.tests.javasupport.statements.SwitchBreak                       arrow-case break crashes ControlFlowStructurer (NoSuchElementException), which XFAIL cannot absorb; separate ticket from D566037730
XFAIL  org.strata.jverify.verifier.tests.javasupport.statements.LabeledContinue                   FRONTEND_OTHER  unconditional labeled continue to the outer loop aborts without a verdict (exit 2)

# --- Uncaught exceptions: an error only if they can actually escape ---
#
# This frontend no longer refuses an unchecked `throw` that a method neither
# catches nor declares: Laurel asserts the throw is unreachable instead, so it is
# reported only when it can happen. It also emits the implicit runtime exceptions
# (ArithmeticException, ClassCastException) as real throws. The source frontend
# keeps its declared-throws refusal and its assertion encoding, which these
# shared fixtures pin. (ImplicitExceptions pins this frontend's output instead,
# with the source frontend's exception in source-xfails.txt.)
XFAIL  org.strata.jverify.verifier.tests.javasupport.exceptions.ThrowDiagnostics   FRONTEND_EXCEPTIONS  'undeclared' is translated and fails verification at its reachable throw instead of being refused
XFAIL  org.strata.jverify.verifier.tests.javasupport.exceptions.TryWithResources   FRONTEND_EXCEPTIONS  the desugared re-throw is no longer refused, so 'useResource' is refused later, at the desugared addSuppressed call
