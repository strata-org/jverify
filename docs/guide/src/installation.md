# Installation

JVerify is built from source. The commands on this page are for the internal package `StrataJavaFrontEnd`; all of them are in [Building from the internal package](#building-from-the-internal-package).

## What JVerify needs

JVerify does not test a program by running it. It translates the program into small logical statements and proves each one. This guide calls such a statement a *check*: for example "this `+` does not overflow", or "the result is what the method promises".

A verification run involves three kinds of program:

- **Java** runs the verifier, the program you start. The verifier compiles your file and translates it.
- The **Strata back-end**, a program called `strataLaurel`, receives the translated program, splits it into checks and reports which of them hold.
- An **SMT solver** is a program that decides whether a logical statement is always true. The back-end calls it for each check.

All of them must be on the `PATH` of the shell you run JVerify in. You do not install any of them yourself: the build described below downloads them, and its step 3 puts them on your `PATH`.

| Tool | Version | Check with | Needed for this guide |
|---|---|---|---|
| Java | 25 | `java -version` | Yes. An older Java stops with `UnsupportedClassVersionError`. |
| Strata back-end | the version the build downloads | `which strataLaurel` (it has no version flag) | Yes. |
| [z3](https://github.com/Z3Prover/z3) | 4.12.6 and 4.15.2 are known to work | `z3 --version` | Yes. It is the SMT solver JVerify uses by default. |
| [cvc5](https://cvc5.github.io/) | 1.3.1 and 1.3.4 are known to work | `cvc5 --version` | No. It is a second SMT solver. The examples in this guide verify with z3 alone; JVerify's own test suite uses cvc5 as well. |

[Lean 4](https://lean-lang.org/) is needed only if you build the Strata back-end from source yourself.

## Building from the internal package

These steps are for Linux and were run on a workspace created from scratch. On macOS the downloaded `strataLaurel`, `z3` and `cvc5` are Linux executables and do not run; see "Building on macOS" in the package's `CLAUDE.md`.

Two Brazil terms are used below. A *workspace* is a directory that holds the packages you check out and build. A *version set* names the exact versions of everything a package is built with; here that includes Java, the back-end and the solvers.

### 1. Check out the package

Run these in the directory where you keep your workspaces, for example `/workplace/$USER`. The first command creates the workspace there, as a new directory `jverify`:

```
brazil ws create --name jverify --versionSet AWSMoogStrata/development
cd jverify
brazil ws use --package StrataJavaFrontEnd
cd src/StrataJavaFrontEnd
```

You are now in the package directory, `jverify/src/StrataJavaFrontEnd`. All later commands, in this chapter and the next, are run from this directory.

### 2. Build the verifier

```
brazil-build installDist
```

The build ends with `BUILD SUCCESSFUL` and installs the verifier as `bytecode-frontend/build/install/bytecode-verifier/bin/bytecode-verifier`.

Use `brazil-build`, not `./gradlew`. The `gradlew` file in this directory is generated by `brazil-build` and only works in the environment `brazil-build` sets up. There is no `gradlew.bat` in this directory.

What this costs:

- **Time**: about 20 seconds, once the downloads are done.
- **Disk, workspace**: about 130 MB.
- **Disk, downloads**: about 9 GB. Brazil stores them once per machine, outside the workspace, and every workspace shares them. The Strata back-end takes 4.1 GB, cvc5 2.4 GB, z3 1.4 GB, and the two JDKs the build compiles with (17 and 25) 0.5 GB and 0.6 GB.

### 3. Put Java and the back-end on `PATH`

The build made Java 25, the back-end (`strataLaurel`) and both solvers available under the workspace's `env` directory. They are on `PATH` only while `brazil-build` runs, so add them for your shell:

```
export PATH="$(cd ../.. && pwd)/env/JDK25-1.0/runtime/jdk-25/bin:$PATH"
export PATH="$(dirname "$(brazil-build-tool-exec which strataLaurel)"):$(dirname "$(brazil-build-tool-exec which z3)"):$(dirname "$(brazil-build-tool-exec which cvc5)"):$PATH"
```

The first line adds Java 25; `../..` is the workspace directory, two levels above the package directory. The second line adds the back-end and the two solvers. Both lines last for the current shell only, so run them again from the package directory in every new shell.

### 4. Check the tools

```
$ which strataLaurel
<workspace>/env/Strata-4.34.x_dev/runtime/bin/strataLaurel
$ java -version
openjdk version "25.0.5" 2026-10-20 LTS
$ z3 --version
Z3 version 4.12.6 - 64 bit
```

`<workspace>` stands for the path of your workspace directory. `java -version` prints two more lines that name the vendor and the build of the JDK; they vary and do not matter, as long as the first line shows version 25.

A run of the first example now takes about 2 seconds. You are ready for [Running JVerify](./first_verification.md).

### Optional: run a back-end you build yourself

Only if you develop Strata itself. Skip this section if you did step 3.

JVerify can run the back-end from the Strata sources in your workspace instead of the downloaded `strataLaurel`. Name the workspace's `src` directory, the one that contains `StrataCLI`, in one of two ways. Either set a variable:

```
export JVERIFY_STRATA=<workspace>/src
```

or pass an option on each run, after the file name:

```
./bytecode-frontend/build/install/bytecode-verifier/bin/bytecode-verifier FILE.java --strata <workspace>/src
```

JVerify then runs `lake exe strata` in `StrataCLI`. `lake` is the build tool of Lean, the language Strata is written in; the command builds the back-end if necessary and starts it. This route needs:

1. The `Strata` and `StrataCLI` packages checked out and built in the same workspace: `brazil ws use --package Strata --package StrataCLI`, then `brazil-build` in `src/Strata` and in `src/StrataCLI`. The two builds took 12 minutes and 3 minutes and grew the workspace to about 10 GB.
2. Lean's `lake` on `PATH`.
3. Java 25 and `z3` on `PATH`, as in step 3.

The first run afterwards took a minute longer while `lake` built the back-end. `--strata` overrides `JVERIFY_STRATA`, and either one overrides `strataLaurel` on `PATH`.

### If something goes wrong

| What you see | What it means | What to do |
|---|---|---|
| `command not found: java` from `java -version` (bash words it `java: command not found`). From JVerify: `ERROR: JAVA_HOME is not set and no 'java' command could be found in your PATH.`, followed by two lines about `JAVA_HOME`; exit code 1 | This shell has no Java on `PATH`. | Run the first `export` of step 3 in this shell. |
| `UnsupportedClassVersionError: ... (class file version 69.0) ...`, exit code 1 | JVerify was started with a Java older than 25. | Run the first `export` of step 3, which puts Java 25 first on `PATH`. If `JAVA_HOME` is set to an older Java, unset it. |
| The shell reports `no such file or directory` for `./bytecode-frontend/build/install/bytecode-verifier/bin/bytecode-verifier`; exit code 127 | You are not in the package directory, or step 2 did not run. | `cd` to `src/StrataJavaFrontEnd` in your workspace. If the file is missing there, do step 2. |
| Four lines: ``Failed to run `strataLaurel` from PATH (pass --strata <path> or set JVERIFY_STRATA)``, then `Error message: Cannot run program "strataLaurel": ...`, then `Verification did not complete (exit code -1); reporting as failed.`, then `Found 1 errors`. The exit code of the command is 255. | The back-end was not found. Nothing was verified. The `-1` in the third line is an internal status, not the exit code of the command. | Run the second `export` of step 3 in this shell. |
| `Not a Strata project directory (--strata): DIR has no StrataCLI subdirectory`, or the same with `(JVERIFY_STRATA)`, followed by the usage text; exit code 2 | `--strata` or `JVERIFY_STRATA` names the wrong directory. | Name the workspace's `src` directory, not the package directory, or unset it and use `PATH`. |
| A first line `Note: 59 error(s) could not be attributed to a specific method; ...`, then many lines with `SMT Solver Crash! stderr:could not execute external process 'z3'`, each followed by a line `strata-unattributed(1:1-1:1): Error: malformed diagnostic from Strata: solver stdout:`, then `Found 78 errors` (the two numbers are those of the first example); exit code 4 | The back-end ran but could not start z3. The number in the `Note` line and the three counters are lower than the number of errors, so go by the error lines. | Run the second `export` of step 3 in this shell. |
